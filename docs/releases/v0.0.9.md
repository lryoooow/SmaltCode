# SmaltCode v0.0.9 · 全仓底层深度审计、安全边界闭环与多模型稳定性加固

**Windows x64 + macOS 13+ (`arm64` / `x64`) 公开测试版。** 欢迎体验并通过 [GitHub Issues](https://github.com/lryoooow/SmaltCode/issues) 反馈问题与建议。

## 本次针对底层问题的深度治理与优化

`v0.0.9` 对 `@smalt/kernel`、`@smalt/desktop`、`@smalt/cli` 及双端构建流水线进行了全仓源码级彻查，系统性修复了 **36 项底层隐患与边界缺陷**。

### 1. 安全边界、路径逃逸防护与权限规则引擎闭环

- **Windows / NTFS / 悬空软链接防护（`workspace-guard.ts`）**：
  - 全面拦截 NTFS 备用数据流（`file.txt:stream` / `::$DATA`）、盘符相对路径（`D:foo.txt`）与尾部空格/点号变体；
  - 修复 `realPathOf()` 在目标尚不存在或为悬空符号链接（Dangling Symlink）时退回词法路径的问题，改为逐级递归解析真实目标（深度上限 16），杜绝通过软链接越界读写；
  - 修复根目录工作区（`/` 或 `D:\`）双斜杠拼接导致敏感文件漏检的问题。
- **Shell 词法解析与权限规则严谨化（`permissions/rules.ts`, `permissions/service.ts`）**：
  - `splitCommand` 支持引号内外 POSIX 反斜杠转义（`\"`、`\'`、`\\`），对未闭合引号、转义引号歧义或未包裹的 `(...)` / `{...}` 子 Shell 严格采取 fail-closed（降级为显式审批）；
  - 支持 `shell:rm *`、`ssh_exec:ls *` 等尾部/内联 `*` 通配规则匹配，并自动剥离 `(`、`sudo`、`env`、`command`、`nohup`、环境变量赋值及二进制全路径前缀，确保 `deny` / `ask` 与高危命令兜底不可绕过；
  - 扩展命令注入检测覆盖 `@(...)` 与 `${var:=...}` 副作用展开；
  - 文件 `allow` 规则强制基于 `realPathOf` 归一化路径匹配，彻底封堵 `src/../package.json` 越权命中 `write:src/**`。
- **工具编排与技能读取隔离（`tools/orchestrator.ts`, `skills.ts`）**：
  - 禁止 `shell` 直接读取或切换进入 `smaltHome()` 应用私有数据目录；
  - Windows 下检测工作区同名本地可执行文件抢占系统 `PATH` 并强制要求人工确认；
  - 保证显式 `ask` 规则不被 `PreToolUse` Hook 的 `allow` 静默跳过，修复并发批量审批唤醒及工具级 `ask: ["grep"]` 审批通过后的结果过滤问题；
  - 限制 `node -e` / `python -c` 等内联解释器调用点击“始终允许”时仅保存精确命令而非 3 词宽泛前缀；
  - 为 `activate_skill` 的伴随参考文件（`referencePath`）增加工作区目录授权与远程 SSH / 容器会话隔离校验。

### 2. 项目工作区体验、Hooks 恢复与对话分叉（Fork）完整闭环

- **项目默认目录自动采用与发送竞态修复（`App.tsx`, `file-context.ts`, `file-context-tools.ts`, `context-files.ts`, `assessment.ts`）**：
  - 在配置了默认工作目录的项目中新建对话时，自动采用已授权的 `projectDefault` 目录作为执行位置（同时提供“改用独立本地空间”一键切换按钮），并在 `send()` 中同步等待项目环境就绪，彻底解决选定项目后立即发送消息误落入空白 `LocalSpace` 的异步竞态；
  - `resource_list` 与环境提示向模型公开已授权可写 `workspace` 的真实路径（保持只读 `source` 路径不暴露），并为 `resource_read` 新增 `offset` / `limit` 行级分页读取参数，避免大文件单次读取撑爆上下文；
  - `searchContextFiles` 原生支持 `*`、`*.md`、`src/**/*.{ts,py}` 等通配符查询，并将目录遍历队列上限从 200 提升至 5,000（访问上限 50,000），修复大型多包仓库深层目录被静默漏扫的问题；
  - `isSupersededOperation` 覆盖 `resource_read`、`resource_search`、`ssh_read`、`container_read` 的同轮重试成功归并，消除参数探索重试导致的“仍有事项需处理”误报。
- **桌面端本机 Hooks 全面恢复（`bridge.ts`, `kernel.ts`, `hooks/bus.ts`, `settings.ts`）**：
  - 解耦 `setExecutionContext` 环境提示文本与远程目标隔离布尔位，恢复本机普通对话的用户级与已信任项目级 Hooks（SSH、容器及无人值守托管子任务继续严格隔离）；
  - 多层配置合并保留用户级与项目级 `hooks` 列表；`HookBus.fork` 完整继承父链钩子，且 `runCommandHook` 超时升级为整棵进程树清理（Windows `taskkill /T /F` / POSIX `-pid`）并销毁管道防死锁。
- **对话分叉 `/fork` 与动态上下文加固（`bridge.ts`, `thread-manager.ts`, `SshWorkbench.tsx`, `ContainerWorkbench.tsx`）**：
  - 桌面端分叉对话时完整克隆 `FileContexts` 关联资料、为 `LocalSpace` 分配独立新目录副本，并同步克隆 SSH / 容器待重连绑定状态（允许工作台识别并解绑）；
  - 修复按消息节点 `upToItemId` 分叉时误吞同轮后续工具与回复的问题，并在轮中截断时自动补齐 `turn-ended` 防止重启误判为崩溃中断；
  - 修复 `@terminal` 预览丢失 `threadId`、`@git:diff` 在零提交新仓库报错、SSH/容器会话阻断本地 `@git:*` 与 `/init`，以及 `/init` 返回字段 `existed` 对齐问题。

### 3. 多模型流式适配器、子智能体与执行内核打磨

- **流式断流防护与思考块协议对齐（`sse.ts`, `anthropic.ts`, `responses.ts`, `chat.ts`, `catalog.ts`, `util.ts`）**：
  - `parseSseEvents` 在 `AbortSignal` 取消时抛出标准 `AbortError` 并冲刷末尾无换行残留帧；
  - `AnthropicAdapter` 与 `ResponsesAdapter` 严禁在未收到 `message_stop` / `response.completed` 时伪造 `done`，防止网络断流导致半截工具参数被执行或摘要损毁对话历史；
  - `AnthropicAdapter` 完整采集并回放带签名的 `thinking` 与 `redacted_thinking` 内容块，并根据 `reasoningEffort` 动态上调默认 `max_tokens`；
  - 支持 OpenRouter 等聚合网关的多段模型 ID（如 `openai/gpt-4o-mini`、`openrouter/anthropic/...`）解析与会话恢复；`ModelCatalog` 磁盘缓存保留 `preferredWire: "responses"`；
  - `ChatCompletionsAdapter` 兼容部分本地/兼容后端首帧空字符串 `tc.id: ""` 并在思考模式工具链中补齐 `reasoning_content: ""`；
  - 全局文本截断引入 `wellFormedUtf16` 清理孤立 UTF-16 代理项，杜绝含 Emoji / 生僻字长输出截断后引发 API JSON 400 错误。
- **子智能体、补丁寻址、静态诊断、检查点与状态机（`subagent.ts`, `apply-patch`, `diagnostics.ts`, `checkpoints.ts`, `turn-runner.ts`, `ProcessSupervisor.cs`）**：
  - `delegate_task` 子智能体继承宿主 `inputGuard` / `scopeFilter`，并将产生的文件检查点（Checkpoint）与 Token 消耗完整归属父对话；
  - `apply_patch` 接入 `@@ anchor` 上下文锚点优先寻址（精准区分重复代码块与纯新增块位置）并支持 Windows / macOS 大小写重命名；
  - `diagnostics.ts` 消除对 `.tsx`/`.jsx` 文本节点、`return /regex/` 正则字面量、ESM `import.meta` 及独立 `=======` 分隔线的假阳性语法误报；
  - `CheckpointStore` 对超过 2 MB 或硬链接（如 `pnpm` 依赖）的合法文件优雅跳过快照而非阻断编辑写盘；
  - `TurnRunner` 与 `SessionRunStateMachine` 实现 `RunPolicy` 真实 Token 对账与失败重试预留退还、$O(1)$ 增量流式 Token 估算、延迟空白前置流气泡通知，并对并发工具审批进行引用计数；
  - Windows `ProcessSupervisor.cs` 固定启动时刻消除睡眠/休眠唤醒后的系统时钟漂移误杀，将活动进程池上限从 64 提升至 512；`browser-network` 与 `integration-network` 支持 `localhost` 从 `127.0.0.1` 自动回退 IPv6 `[::1]`。

### 4. Windows & macOS 打包管线修复

- **macOS 官方签名与 `--adhoc` 签名闭环（`build-desktop-mac.mjs`, `electron-builder.mac-adhoc.yml`, `sign-mac-adhoc.cjs`）**：
  - 官方签名模式在调用 `electron-builder` 前自动剥离 `CSC_NAME` 的 `Developer ID Application:` 前缀，解决校验策略与 `electron-builder` 证书查找器的冲突；
  - `--adhoc` 社区打包模式新增自定义签名钩子 `sign-mac-adhoc.cjs`（调用 `@electron/osx-sign` 执行真实 `-` Ad-hoc 签名），确保 Apple Silicon 运行要求及 `codesign --verify --deep --strict` 严格校验通过。

## 安装与校验

### Windows x64

下载 **SmaltCode-Setup-0.0.9-SFox.exe**，使用 **SHA256SUMS.txt** 核对哈希（Windows 安装包未做商业代码签名，系统可能提示未验证发布者）：

```powershell
Get-FileHash .\SmaltCode-Setup-0.0.9-SFox.exe -Algorithm SHA256
# SHA256: 4b637f63ce1353e554ec040bcbc55f09e8bdcd01a20a054c8c7cffdad0481596
```

### macOS 13+（Apple Silicon `arm64` / Intel `x64`）

可通过仓库 GitHub Actions 中的 `Package macOS Desktop (Manual)` 手动触发生成 **SmaltCode-0.0.9-macOS-arm64-adhoc.dmg** 与 **SmaltCode-0.0.9-macOS-x64-adhoc.dmg**（也可在 macOS 本地执行 `node scripts/build-desktop-mac.mjs --adhoc`）。拖入 `/Applications` 后，首次打开前如遇 Gatekeeper 提示，请在终端执行：

```sh
xattr -cr /Applications/SmaltCode.app
```
